# Cardputer ADV bug fixes — September 9, 2026

## Changes

| Area | Corrected behavior |
| --- | --- |
| AI move ordering | Signed indexing now covers all 218 move slots without writing before the stack arrays. |
| AI search | Terminal positions are evaluated before stand-pat cutoffs at the horizon. Mate scores use actual search distance. Checking extensions stop at a total depth of 12 to bound ESP32 stack usage; deadline comparisons tolerate millisecond-counter rollover. |
| Chess960 | When an ordinary king move and castling share a destination, a dialog offers King, Castle, or Cancel. Both moves remain available. |
| Keyboard | Every poll compares key identities and services held-key repeat. Swaps with the same number of keys are detected, repeat retains modifiers, and the side button remains pressed between its initial press and hold threshold. |
| Puzzle turns | Grid actions cannot move during animations or an opponent turn. Autoplay executes only opponent steps and matches promotion choices. The player must enter the final move. |
| Puzzle display | Move-list reconstruction starts from the actual puzzle position. Puzzle identity and retry feedback survive status refreshes. |
| Repetition | Only legally capturable en passant targets distinguish repetition positions, including pin checks. The network synchronization hash remains unchanged. |
| Long games | The latest 250 plies remain available to repetition detection after the full-game review limit. The displayed move list remains bounded. |
| Save migration | Validated v1 records receive complete moved-piece metadata, allowing Resume, undo, and current-format encoding. |
| Timeout | Local and peer timeout decisions consider the non-flagging side's mating material. A bare king cannot receive a timeout win. Incorrect peer outcomes and timeout claims in untimed games are rejected. |
| Material draws | Multiple bishops confined to one square color are handled, including promoted bishops. |
| Canvas | Horizontal and vertical lines wholly beyond the canvas return before unsigned clipping can overflow and overwrite the heap. |

Timeout and repetition behavior follows the relevant material and position-identity
rules in the [FIDE Laws of Chess](https://handbook.fide.com/chapter/e012023).
The per-side material test accounts for enemy pieces that may enable mate, consistent
with the approach described in [python-chess's material detection](https://python-chess.readthedocs.io/en/latest/core.html#chess.Board.has_insufficient_material).
As with that approach, it does not solve arbitrary locked positions or forced lines
to prove every possible dead position.

## Save compatibility

The save format is now v7. Its size and CRC32 framing match v6, but an overflowed
history contains the most recent moves instead of the first 250. Decoding validates
the retained sequence before making any output state visible. Full-game undo/review
remains unavailable once earlier moves have been dropped.

Existing v1-v6 saves remain supported. For a legacy overflow save, the old prefix
is validated, then discarded because the intervening moves were never saved.
Repetition tracking restarts at that saved board and is preserved across subsequent
saves. Participants and the board remain in the same atomic NVS blob. Newly written
v7 saves require this firmware or a later compatible build to resume.

The network protocol is now v6 with the same packet layout. Both players need
updated firmware: older peers can disagree about timeout draws or repetition.
Existing version checks reject that pairing before a game starts.

## Verification

- All 85 PlatformIO native tests pass, including updated save migration and overflow cases.
- The host regressions pass under AddressSanitizer and UndefinedBehaviorSanitizer.
  Run `python3 test/host_regressions/run.py`; see its accompanying README for coverage.
- The Cardputer ADV target compiles successfully with the pinned ESP32 platform and
  libraries. Static RAM usage is 74,044 / 327,680 bytes (22.6%); flash usage is
  973,465 / 3,145,728 bytes (30.9%). Firmware packaging and manifest generation also pass.
- No device was attached. Physical keyboard, display, radio, and power-loss behavior
  remain unverified on hardware.

Existing workspace changes were preserved. The packaging protocol gate and development compatibility notes were updated to match protocol v6.
