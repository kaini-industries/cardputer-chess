## What's New

v0.20.0 is the first post-testing improvement release for Cardputer ADV Chess,
with conventional clocks, significantly more reliable ESP-NOW multiplayer,
persistent player profiles, clearer controls, and safer saved-data handling.

> **Multiplayer compatibility:** both devices must run v0.20.0 or another
> protocol-v6 build. Earlier multiplayer protocol versions are intentionally
> rejected. Upgrade or roll back both Cardputers together.

### Clocks & Timed Play

- Use conventional chess-clock behavior: White's clock starts when the board is
  ready, and Black's clock does not start until White completes the first move.
- Stop the mover's clock, apply increment, and start the opponent's clock as one
  deterministic transition.
- Synchronize timed online games with per-player authoritative clocks and
  heartbeat correction of the active remote clock.
- Carry the mover's post-increment time with each acknowledged online move.
- Let a player give the opponent **+15 seconds** in a timed online game, with
  confirmation and acknowledged exactly-once delivery.

### Multiplayer Reliability & Identity

- Show each host's profile name and MAC suffix alongside its variant and time
  control before joining.
- Retry pairing requests and game-start packets until they are acknowledged.
- Bind protocol-v6 traffic to nonzero game and session IDs, the selected peer
  MAC, and monotonic sequence numbers.
- Acknowledge moves and protect the board from stale, duplicated, or divergent
  packets with position epochs and hashes.
- Keep clock heartbeats, draw responses, time gifts, and terminal results inside
  the same validated session.
- Add in-game draw offers and synchronized draw responses.

### Profiles & Recent Results

- Create, rename, select, and delete up to four persistent player profiles.
- Use the active profile name automatically for AI and online games; Local games
  can assign a profile or Guest independently to White and Black.
- Track per-profile games, wins, losses, and draws.
- Store the 16 newest completed-game summaries, including participants, result,
  finish reason, mode, variant, time control, ply count, and final clocks.
- Journal terminal results so an interrupted storage update can be recovered
  without double-counting a completed game.

### Controls, Help & Review

- Make **Space** cycle legal destinations for the selected piece; it no longer
  acts as Enter.
- Cancel a selected move with **Esc**, **Delete**, or **Backspace**, with the
  cancellation hint visible at the bottom right.
- Toggle between sprite and letter pieces with **B**.
- Open contextual controls help with **H** or **I** (`H` remains Hint in
  puzzles).
- Label the review counters explicitly: **Ply current/total** at top left and a
  White-relative pawn evaluation or terminal result at top right.
- Offer draw with **D**, give time with **G**, and keep review unavailable during
  live timed or online play until the game ends.

### Chess, Puzzles & Device Fixes

- Prevent AI move-ordering stack corruption in positions with many legal moves
  and prevent offscreen line drawing from overwriting the graphics buffer.
- Detect held-key repeats and same-count key swaps; preserve Fn modifiers and
  side-button state.
- Offer an explicit choice when a Chess960 king move and castling share the
  same destination.
- Keep puzzle opponent turns under automatic control and require the player
  to enter the final move. Preserve correct notation and retry feedback.
- Recognize checkmate and draws at the AI search horizon, use distance-based
  mate scores, and bound checking extensions for the ESP32 task stack.
- Correct repetition when an en passant capture is unavailable or pinned, and
  retain recent moves for repetition after the full-game review limit.
- Draw on timeout when the non-flagging side lacks mating material; apply the
  same decision on both multiplayer peers. Handle promoted same-color bishops.
- Restore complete moved-piece information when resuming v1 saves.

### Saved Data & Migration

- App-only upgrades at `0x10000` preserve NVS profiles, saves, results, puzzle
  progress, and settings when the existing partition layout is compatible.
- Existing v1-v6 Local and AI saves remain readable. On successful resume they
  are validated, assigned safe participant metadata, and rewritten atomically
  in the current v7 save format. Legacy overflow saves restart repetition
  tracking at the saved board because their recent moves were not retained.
- The first v0.20.0 launch creates a default **Player** profile with empty
  statistics and history when no profile record exists. Games completed before
  v0.20.0 are not reconstructed retroactively.
- Corrupt or newer unsupported storage records are preserved rather than
  overwritten with defaults.
- A clean factory installation that erases flash removes saved games, profiles,
  results, puzzle progress, and settings. Online sessions remain non-resumable.

### Deferred Larger Enhancements

Full multiplayer premoves, complete-game replay archives, and a dedicated win
celebration remain deferred to later releases.

## Binaries

These binaries target the **M5Stack Cardputer Advance with 8 MB flash**.

| File | Flash offset | Description |
|------|-------------|-------------|
| `cardputer-chess-0.20.0-m5-burner.bin` | `0x0000` | Complete factory image for M5Burner/manual installation, including bootloader (`0x0000`), partitions (`0x8000`), OTA selector (`0xE000`), and app (`0x10000`) |
| `cardputer-chess-0.20.0-app.bin` | `0x10000` | App-only image for a compatible in-place upgrade that preserves data partitions |
| `firmware.bin` | `0x10000` | Byte-identical compatibility alias of the versioned app image |
| `cardputer-chess-0.20.0-cardputer-advance-flash-bundle.zip` | Multiple | Manual/recovery bundle with individual components, exact offsets, and flashing instructions |
| `cardputer-chess-0.20.0-debug.zip` | Not flashable | ELF and map files for crash diagnosis |
| `release-manifest.json` | Not flashable | Version, source commit, target, protocol, flash layout, sizes, tool versions, and artifact hashes |
| `SHA256SUMS` | Not flashable | SHA-256 checksums for release-artifact verification |

Use the complete image only at `0x0000`. Use the app image or `firmware.bin`
only at `0x10000`. A clean factory erase is destructive; an app-only update does
not erase compatible NVS or data partitions.

## Validation

The published release records its exact source commit, CI run, image sizes, and
checksums. `release-manifest.json` identifies the source commit, compiler and
PlatformIO versions, protocol, flash components, and hashes for the attached
artifacts. `SHA256SUMS` verifies the complete download set.

Automated coverage includes all 85 native tests and the engine/scene regressions
under AddressSanitizer and UndefinedBehaviorSanitizer. The latter cover 218 legal
moves, standard depth-4 perft, input state, Chess960, puzzle turn ownership, save
migration, timeout agreement, and repetition after a 260-ply game. The release
workflow also checks the production build, partition limits, image layout,
manifest, checksums, and ESP32-S3 image integrity.

Physical-device validation remains **unverified**: factory installation, app-only
upgrade and power-cycle data retention, two-device ESP-NOW play, older-protocol
rejection on hardware, and installation through the M5Burner catalog. These
checks have not been represented as passed.

The GitHub release provides the M5Burner-compatible factory binary. The separate
M5Burner catalog entry has not been updated or validated as part of this release.
